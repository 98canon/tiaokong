# 维护时的验证

维护 skill 本体时用。按改动类型定跑什么，能用静态核对确认的，就不运行脚本。

| 改了什么 | 跑什么 |
|---|---|
| 只改规则文字 | `docs/tools/check-paths.ps1`（路径都存在、编码正确）；派一路只读审查，查前后矛盾 |
| 改文件名或路径 | 上面这些，再搜旧名字有没有残留引用 |
| 改脚本里会执行的代码 | 先静态核对：语法解析、读一遍改动、确认改到的路径和参数存在。确实只有实际运行才能确认时，才跑冒烟，而且先告诉用户为什么要跑、跑什么、要多久，用户同意再跑 |
| 改脚本逻辑 | 派子代理在沙盒实测，限时；同一条失败两次就停下写报告。也要先问用户 |

- 只改注释，或者只改了文档里怎么写脚本的名字，不算改了会执行的代码，不跑冒烟。
- 子代理测试一律限时。同一条失败两次就停下写报告，不无限重试。
- 审查报告写在仓库外的维护目录，不放进仓库。

## 主控脚本维护的本地测试分工

只针对 `scripts/control/` 的维护。先静态核对语法、改动、参数和路径。确需运行时，先说明原因、范围和预计耗时，未获用户授权仍先问。用户明确授权主会话本地统一测试后，使用以下分工，不套用启用 skill 的运行调度，也不放宽其他任务的子代理守则。

- 测试作者独立按已审接口写断言，不读同批实现。只写测试并做语法等静态检查，如实报告「仅编写并语法检查，运行移交主会话」，未做的检查另列，不冒称实跑。
- 主会话是本地执行者。在隔离夹具做空 ControlRoot 的前置失败验证、已知错误桩验证、正式执行、临时实现副本反向验证、复跑和清理。测试和审查复跑都由主会话执行，不派沙盒实跑代理。不得修改正式实现做反向验证。
- 固定审查者独立核对代码、断言和原始 stdout、stderr、退出码、超时、耗时、命令及清理结果，注明命令由主会话执行，不冒称亲跑。日志未齐不算测试完成。
- TempRoot 必填，须预先存在、为绝对目录且不在系统盘。每份测试只用其中自己的唯一目录。ControlRoot 可选，仅指向 TempRoot 内无重解析点的空实现或临时副本，不指向正式实现。CleanRepoSeed 可选，由主会话在 TempRoot 内提供或构造干净仓库夹具，总入口执行时按需传入。Git 夹具用命令级假身份，不改用户配置。

总入口由主会话执行，参数路径先存变量，不拼可执行字符串：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File docs/tools/test-control.ps1 -TempRoot $tempRoot
```

需要干净仓库夹具时追加 `-CleanRepoSeed $cleanRepoSeed`，不是必填。脚本在 Windows PowerShell 5.1 运行，不承诺跨平台。每个被测子进程硬限 30 秒，单测试内部预算 120 秒，总入口给单测试 135 秒，自身 750 秒，主会话外层 840 秒，预留清理余量。只终止自己启动的进程。同一问题失败两次停报，不无限重试。

锁与写入门禁按深度验证连跑五次，其他定向测试三次，最终全套一次。关键反向验证至少覆盖登记不覆盖、锁不双拿、release 不删别人、guard 识别变动、section 不泄漏、阶段表列表外正文不损坏。记录错误副本确实失败及恢复结果。未运行、失败和 unknown 项如实列出。正式文件齐备后再由主会话跑 `docs/tools/check-paths.ps1`。这些是验收要求，不代表已经通过。

## 编码

- Markdown：UTF-8 无 BOM，LF。
- `.ps1`：UTF-8 带 BOM（Windows PowerShell 5.1 读不带 BOM 的脚本会把中文读坏）。

## docs 的用法

- `docs/` 只用于维护 skill 本体，启用 skill 时不读。
- `docs/` 入库，会公开在 GitHub 上。这里只放通用内容，不写盘符、用户名、具体供应商和模型。
- `docs/plans/`：进行中的优化方案。审查确认、合入之后，移进 `docs/archive/plans/`。
- `docs/archive/`：不入库，只在本地。
- `docs/basis/`：用户的原始规则原文。改规则时和 `SKILL.md` 一起改，避免两套口径。
- `docs/path-map.md`：2.3.0 的路径对照。
