# 代码审查任务

## 范围
- 只审查本次 diff:<git diff 范围或文件列表>
- 方案/需求依据:<方案文档路径或一句话目标>
- diff 之外的代码只用于理解调用关系,不对其提问题。

## 只报告以下问题
1. 阻断:会导致错误行为、数据损坏、权限绕过、崩溃、破坏现有调用方。
2. 应修:有明确触发条件的边界缺陷,如空值、重复提交、分页、并发覆盖、资源未清理。

## 不要报告
- 命名、格式、注释、代码风格,除非违反项目规则文件中的明确条款。
- 与本次目标无关的重构建议、"更好的写法"、性能微优化。
- 方案已明确决定的设计取舍。
- 没有具体触发路径的推测性风险。

## 每条问题必须包含
- 位置:文件:行号
- 触发条件:什么输入或操作会出错
- 后果:用户或数据层面会发生什么
- 证据:你读到的具体代码,而不是推断
- 修复建议:一句话即可
无法给出触发条件和证据的,不算问题,放进"待核对"。

## 输出格式
- 结论:可合并 / 修复后可合并 / 不可合并
- 阻断问题(0~N 条)
- 应修问题(最多 5 条,按严重度排序)
- 待核对(需要真机、现网或用户确认的事项,最多 3 条)
没有发现问题时,直接写"未发现阻断或应修问题,可合并",不要为了凑数列出低价值意见。
