# 子代理通用守则

所有子代理必读，和项目规则文件一起使用。项目规则可以加严，不能放宽。审查者、复核者另读同目录的 `review-standard.md`。

## 一、禁止

- 只改派单里「允许修改」的文件和函数。别的子代理可能同时在改别的文件，越界会互相覆盖。确实必须改清单外的文件时，先不改，在报告里说明原因和要改什么。
- 不新建文件，除非派单允许。不删除文件。
- 不做 git 写操作（commit、add、stash、checkout、reset、restore），不改 git 配置。git diff、git show、git status 可以用。提交由主控做。
- 不读、不打印密钥文件（如 `.env`）。不启动服务，不发外网请求，不调用外部模型接口，不安装依赖（确需时停下报告）。
- 不写真实数据目录，不用真实数据库做实验；需要数据就在临时目录里建。
- 不做派单范围以外的重构、改名、格式化或「顺手修改」。
- 名为 `_archive` 的文件夹存放已退役的文件和旧规则，默认忽略：不读、不在里面搜索（搜索时排除它），不把里面的内容当作依据。只有派单明确要求读其中某个文件，或要你往里面挪退役文件时例外。
- 可以读派单里点名给出的路径（包括 skill 目录里的这份守则和审查标准）；除此之外，不读、不改任何项目的调控师目录（`tiaokong-projects`、`tiaokong-registry`、本机配置）和 skill 目录。

## 二、改代码

- 先读相关代码再改，沿用现有风格、命名和库；注释密度和周围一致。
- 保持文件原有的编码、换行符和缩进。不要整文件重写，只改需要改的地方。
- 不把旧代码整段注释掉留着，不留成串空行，不删和本次任务无关的调用。

## 三、测试

- 断言检查真实结果（数据库的行、文件内容、状态），不只看返回码。
- 前置条件用真实接口或服务函数造，不手写不可能出现的数据状态（迁移测试手写旧版本数据除外）。
- 等并发或后台任务用事件、屏障或带超时的等待，不用 sleep。
- 测试只用临时目录或测试夹具给的目录。临时文件不放系统盘（C 盘），结束前删掉。
- 失败保持失败：不删断言、不降级、不用默认值绕过检查。
- 反向验证：每条新增或补强的关键测试，临时把实现改回错误写法跑一次，确认失败，再按原样恢复并确认通过。报告里写清改了什么、失败信息、是否已恢复。前端改动另写浏览器手动验收步骤。
- 只跑派单列出的测试，不跑全量，除非派单写明。所有测试命令都要有超时。

## 四、不许提前返回

- 测试和检查在前台运行，拿到完整输出和退出码之后才能写最终报告。
- 不能以「已启动、等待结果」「稍后再看」结束。没做完就接着做完。
- 详细内容写进报告文件，最终回复只放摘要（不超过 25 行）和报告路径。

## 五、角色

- 单人完成：先按测试合同写测试，确认实现前失败（合同标明「只作回归守护」的除外），再实现，最后反向验证。
- 测试作者：只改派单指定的测试文件；断言只按测试合同定，不参考同批实现者的改动。合同模糊或和代码对不上时不要猜，在报告里列出并写明你的理解。实现还没落地时跑一次，记录每条的失败信息；实现前就通过的测试要改严或说明原因。
- 实现者：只改业务文件，不改测试作者的文件。契约变化必须改已有测试时，只改派单列明的，并逐条列出。测试作者的测试失败时，先查自己的实现；确认是测试写错，不改测试，在报告里写明交给主控。
- 修复者：只修派单给的修复清单，每条附反例测试。
- 预调研：只读，只写指定的报告。产出：前置依赖核对（按实际代码列函数签名）；和现有代码的冲突点（文件、行号、关键代码摘录）；测试合同（编号、函数名建议、场景、前置条件怎么造、预期结果、实现前是否就会通过）；实现计划（按文件和函数，写到照着改就行，容易做错的边界逐条写出正确行为）；需要主控决定的问题（选项和推荐项）。
- 审查、复核：按 `review-standard.md`。

## 六、报告

写到派单指定的路径。按顺序，没有内容的写「无」：

0. 第一行：执行方和档位，例如 `<供应商>/<模型>#<档位>`
1. 改动文件清单：每个文件一行，改了什么、大致行号。只读任务写「无」。
2. 关键决定：偏离方案或自行定下的点，各一句理由。
3. 命令与退出码：每条实际运行的命令、结果摘要和退出码。
4. 报告路径。
5. 反向验证：做了哪几条、改了什么、失败信息、是否已按原样恢复。
6. 延期项：没做完或留给后续的事，写原因。
7. 需要用户拍板的问题：每条写选项和推荐项。
8. 浏览器手动验收步骤：有前端改动时写。

最后一行写完成短语：`已完成`，或者 `无法完成：<一句话原因>`。
