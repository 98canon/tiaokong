# 调控师

OpenCode 的 skill：主会话担任总控，按指定方案把开发任务派给子代理，负责启用自检、规划、派单、选档位、并发、验证层级、多路审查、提交和汇报。

## 安装

仓库地址：<https://github.com/98canon/tiaokongshi>

```
git clone https://github.com/98canon/tiaokongshi.git
```

1. 把克隆下来的目录放到任意位置，再在 `~/.config/opencode/skills/` 下建一个名为 `调控师` 的目录联接指向它（Windows：`mklink /J`），或直接复制过去。仓库名是 `tiaokongshi`，联接名仍用 `调控师`。
2. 按 `templates/本机配置.example.md` 写一份 `~/.config/opencode/调控师-本机.md`。本机配置只写机器事实，以及你认可的「可信来源」。模型核验和每个模型的表现记在全机共用的 `~/.config/opencode/调控师-模型记录.md`（格式见 `templates/模型记录.md`），由调控师在调研和每批审查后写，不用手填。
3. 每个项目第一次 `@调控师` 时会做绑定，按 `templates/登记.md` 新建登记文件。项目档案按 `templates/项目档案.md` 写，放在项目仓库以外，可以沿用原位置。

## 开发和安装分开

开发和维护在 `<开发克隆>` 里做（改规则、审查、`_archive/` 都在这里）。改完提交推送，这时还不生效。`~/.config/opencode/skills/调控师` 放另一份只用来拉取的克隆 `<安装克隆>`（直接克隆到这里，或用目录联接指过去）。发布时执行 `git -C <安装克隆> pull --ff-only`。`<安装克隆>` 不要直接改。自检的「版本」一项会看它的 `git status`。

在 `<开发克隆>` 根目录建一个空文件 `.tiaokong-dev`（不入库）：`New-Item -ItemType File .tiaokong-dev`。有这个标记，调控师加载时会认出这是开发仓库，警告并停下，不会被当作 skill 使用。`AGENTS.md` 写了在开发仓库里打开会话时的规矩。

## 使用
在 OpenCode 里写 `@调控师`。进入时先绑定当前项目，旧项目第一次会问一次项目标识和档案路径。

- 还没有方案：完整调研、制定方案、启用自检、按批开发。制定方案时先选方向：省钱、高效、均衡、沙盒，默认推荐做得到的均衡。价格相同但能力不同的模型，由你选用哪一个。四个方向都做不到时，会如实说明，并问你是否只用 `规则/` 下的两份文件；都不用就结束，不改任何东西。
- 同一个方向写第二份方案，默认叫 `均衡方案2.md`、`均衡方案3.md`，也可以自己起名。
- 已有方案并写了名字，例如 `@调控师 均衡方案`：先做紧要调研。没有冲突就按这份方案继续；有冲突就停下来，等你选。
- 已有方案但没写名字：停下来问，推荐档案里的「当前方案」，没有才推荐第一份。

探测只对准方案里实际执行任务的模型，同一次启用里每个模型只探测一次。说「换成方案 Y」或「取消调控师」时切换或退出。

## 目录
- `SKILL.md`：主控规则。没有方案时走完整调研；已有方案并写了名字时走紧要调研。
- 方案在各项目自己的 `~/.config/opencode/调控师-项目/<项目标识>/方案/`，项目之间不互读。一份文件一个方案。
- `references/预置方案/`：占位符示例。Skill 运行时不读，不占上下文。
- `规则/`：子代理通用守则、审查标准。和预置方案分开，不启用 skill 的项目也可以直接引用。
- `templates/`：派单骨架、项目档案、`登记.md`、`模型记录.md`、`阶段表.md`、本机配置示例、沙盒规则头。
- `scripts/`：沙盒类方案用的通用 PowerShell 脚本：`new-sandbox.ps1`、`run-tool.ps1`（内部调用 `run-tool-inner.ps1`）、`check-sandbox.ps1`、`watch-runs.ps1`、`clean-sandbox.ps1`、`copy-back.ps1`。`adapters\agy\` 是 agy 的适配。这些脚本存成带 BOM 的 UTF-8。只有当前方案写明要用时才调用。
- `依据/`：用户的原始规则原文。运行时以 `SKILL.md` 为准；改规则时和 `SKILL.md` 一起改。
- `待合入.md`：仓库里已有的这份先留着，启用时不读。新教训写当前项目自己的待合入。
- `_archive/`：已退役的文件，不入库，默认不读。`_archive/优化方案/` 放针对调控师本身的、已经合入或作废的优化方案。

## 改动规则
运行时以 `SKILL.md` 为准。改规则时，`依据/` 和 `SKILL.md` 一起改，避免两套口径。教训默认写进项目自己的待合入，默认路径是 `~/.config/opencode/调控师-项目/<项目标识>/待合入.md`。只对这个项目成立的，用户同意后合进项目规则。所有项目都要遵守的，在 skill 仓库另开维护会话（不启用调控师）改规则，升 `VERSION`，写 `CHANGELOG.md`，用户同意后提交。还原规则用 git。针对调控师本身的优化方案，审查确认没有问题、合入之后，移进 `_archive/优化方案/`。项目的执行方案不放这里。改方案之前先备份：路径写在这个项目的档案里，磁盘由用户指定，只含这个项目的方案，不含 `.git`。一键还原只恢复方案。
