# 派单骨架

主控照这个骨架写派单。通用要求（禁止事项、测试要求、不许提前返回、角色、报告格式）都在 `规则\子代理通用守则.md`，项目要求在项目规则文件里，派单里不重复抄，只写本批特有的内容。

```
# <批次编号>：<一句话目标>（角色：单人完成 / 测试作者 / 实现者 / 修复者 / 预调研 / 审查 / 复核）

先读并严格遵守：
- <skill 目录>\规则\子代理通用守则.md
- <项目规则文件>
- （审查、复核另读）<skill 目录>\规则\审查标准.md，以及项目审查补充（如果有）

## 依据
- <方案、预调研、审查结论或修复清单的路径和条目编号；长文档只给相关段落的摘录>

## 边界
- 允许修改：<文件；大文件写到函数>
- 允许新建：<文件，或「不新建」>
- 禁止修改：<别的批次正在改的文件等>
- 可以运行：<检查命令；超时>

## 改法
- <改哪个函数、改成什么行为；能给伪代码或「正确 / 错误」对照例子就给>

## 边界情况
- <空值、非法输入、重复提交、并发、失败回滚……逐条写期望行为>

## 测试
- <新增哪些用例，每条断言什么真实结果；关键用例写出必须让它失败的错误实现（反向验证）>
- 只跑：<和本批相关的测试文件>

## 审查时另填
- 验证层级：<阶段 / 深度（触发条件） / 全量>
- diff 范围：<git 范围或文件列表>
- 负责方面：<a / b / c / 全部>

## 报告
- 写到：<路径>
- 第一行写：<执行方#档位>
```
